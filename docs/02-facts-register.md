## B. Claims from the pasted third-party message (do not rely on them)

| ID | Claim | Status | Why |
|---|---|---|---|
| D1 | "Primitive recursion lets you prove the robot is safe / never deadlocks." | **DEBUNKED** | Primitive recursion guarantees *termination* of a computation, not physical safety. A terminating program can still output a dangerous action. Safety needs a model of the physics, a spec, and assumptions about sensing/actuation. |
| D2 | "Neurosymbolic Embodied-TM needs ~1/1000 of the compute and beats VLA accuracy." | **UNVERIFIED** | No evidence given; contradicts the fact that contact-rich dexterous manipulation is hard to hand-code. |
| D3 | "COAP beat prior VLA models by 38.9% on RoboDojo; NTU authors; 'broke the robotics circle'." | **UNVERIFIED** | The paper exists (F12) but these numbers/affiliations were not in the snippets seen. Read the paper first. |
| D4 | "Use the halting problem and recursion theorem to derive robot behavior bounds." | **DEBUNKED** as stated | Rice-type results say *general* automatic verification is impossible, which *motivates restricting* the spec and program class (this project's bounded fragment), not a route to bounds. |
| D5 | "Phase-space evolution ≙ Turing-machine transitions; conservation laws as TM constraints." | **DEBUNKED** as a method (metaphor only) | No mechanism offered; physics priors enter via models/constraints (e.g. ATACOM), not via computability theory. |

## C. How to add a row

Add an ID (continue the sequence), state the claim narrowly, set the *lowest honest* status, and cite where you
looked. When you upgrade a status, say what you read. Never delete a `DEBUNKED` row: it prevents repeating mistakes.
